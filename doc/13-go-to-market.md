# Go-to-Market

## Initial wedge

Start with open-source developers and indie builders.

Avoid selling to large enterprises first.

## Supply acquisition

Recruit contributors through:

- open-source communities;
- coding communities;
- university developer groups;
- AI coding communities;
- GitHub;
- Discord;
- developer newsletters.

Message:

> “Have 30 minutes and an AI coding agent? Turn it into useful developer
> credits.”

## Demand acquisition

Recruit builders through:

- open-source maintainers;
- indie hacker communities;
- GitHub repositories;
- developer communities;
- startup accelerators.

Message:

> “Turn the small tasks in your backlog into tasks other developers can
> safely pick up.”

## Launch strategy

Do not launch with thousands of empty tasks.

Instead:

### Cohort 1

10 builders + 25 contributors.

### Cohort 2

25 builders + 100 contributors.

### Cohort 3

Open registration.

Each cohort should only expand when liquidity works.

## Partner rewards

Early partners could provide:

- SaaS trials;
- private beta access;
- API credits;
- developer templates;
- community memberships.

These create credit sinks without requiring the platform to pay cash.

## Growth loop

``` text
Builder posts task
      ↓
Contributor completes task
      ↓
Contributor earns credits
      ↓
Contributor wants to spend credits
      ↓
Contributor posts own project/task
      ↓
New builder/task enters ecosystem
```

This is the desired network effect.

## Reputation loop

``` text
Complete good task
      ↓
Higher reputation
      ↓
Access better tasks
      ↓
Earn more credits
      ↓
Become more valuable contributor
```

## Potential wedge product

A lightweight GitHub app could be enough:

> “Convert selected GitHub issues into credit-rewarded tasks.”

That can be tested before building the full marketplace.
